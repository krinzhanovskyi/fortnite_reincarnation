# Fortnite Reincarnation

Windows-приложение на Python для повторяющегося цикла матчей: распознавание экрана → запуск поиска → ожидание → высадка → простые движения → результаты → новый матч. Перезапуск Fortnite не используется.

**Проект требует калибровки по реальным экранам вашего режима Fortnite.** Готовых достоверных шаблонов игры в репозитории нет. По умолчанию включено наблюдение без ввода. Наличие всех шаблонов проверяется до запуска управления; неизвестные экраны приводят к паузе.

В текущей рабочей папке выполнена калибровка по 25 сохранённым и диагностическим кадрам 1920×1080. Профиль и вырезанные шаблоны находятся в `runtime`, индивидуальные действия и результат проверки каждого кадра — в `runtime/calibration/report.md`. Эти локальные изображения не включены в Git. После обновления кода перезапустите приложение. Калибровка сохраняет выбранный режим наблюдения.

Добавлен вариант наблюдения за союзником с надписью «РЕЖИМ ЗРИТЕЛЯ» сверху по центру во время ожидания карты возрождения. Бот не нажимает игровые клавиши, не ориентируется на имя союзника и не включает меняющиеся секунды в шаблон. После возрождения допускается возврат к управлению своим персонажем; после завершения матча — переход к меню результатов.

Повторить проверку и применение профиля по этим же кадрам можно без отправки игрового ввода:

```powershell
.\.venv\Scripts\python.exe -m reincarnation.capture_profile --apply
```

Перед применением проверяются состояния и фактический выбор действий контроллером для каждого кадра. Предыдущий файл настроек сохраняется в `runtime/calibration/settings.backup.*.json`. Новые, неразмеченные кадры перечисляются отдельно; автоматического угадывания разметки нет. Проверка исходных кадров не заменяет наблюдение за новой игрой.

## Установка и запуск

Windows 10/11, Python 3.11 или новее с Tcl/Tk. Единственная внешняя библиотека — Pillow. Отдельно устанавливать средства компьютерного зрения не нужно.

Из PowerShell в папке проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\start.bat
```

Установщик создаёт `.venv`, устанавливает проект и генерирует `runtime/settings.json`. Для первого скачивания пакетов нужен интернет. Скрипт не меняет постоянную политику PowerShell.

Альтернативная установка:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m reincarnation
```

Запускать следует из папки проекта. Для другого профиля:

```powershell
.\start.bat --data-dir runtime\another-profile
```

## Горячие клавиши

| Клавиша | Действие                                                       |
| ------- | -------------------------------------------------------------- |
| F6      | Начать / продолжить, когда игра на переднем плане              |
| F7      | Пауза и освобождение ввода                                     |
| F8      | Немедленно запретить дальнейший ввод и освободить клавиши      |
| F9      | Поставить на паузу, сохранить снимок игры и открыть калибровку |

Клавиши глобальные и настраиваются в JSON (`F1`–`F11`, все разные). Если Windows не позволяет зарегистрировать одну из них, приложение сообщает об ошибке. Запуск через горячую клавишу позволяет проверить фокус игры до первого действия. Кнопки паузы и остановки есть и в окне приложения.

После ошибки или аварийной паузы бот освобождает ввод и сразу перезапускает рабочий цикл с повторным определением экрана. Fortnite и окно приложения не перезапускаются. Если игра потеряла фокус, бот ждёт возвращения к ней и затем продолжает автоматически. Фокус сам не перехватывается.

Ручные F7/F8, закрытие приложения и F9 для калибровки отменяют автоматический перезапуск. При F8 приложение остаётся открытым; новый запуск возможен через F6. Ручная остановка действует даже во время загрузки настроек для перезапуска.

Параметры раздела `recovery`: `enabled` — включение восстановления (по умолчанию `true`); `max_restarts` — максимум перезапусков при последовательных сбоях (3); `stable_seconds` — время подтверждённой нормальной работы для сброса счётчика (120 секунд). Ожидание фокуса не расходует попытки. После исчерпания лимита бот остаётся на паузе до F6. Счётчик отображается в интерфейсе, причины и попытки записываются как `AUTO RESTART` в журнал. Перезапуск не добавляет шаблонов для неизвестных экранов: если ошибка сохраняется, нужен новый снимок и калибровка.

## Калибровка первого профиля

1. Выберите один режим Fortnite, постоянное разрешение, масштаб HUD и язык. Используйте оконный режим без рамки или обычное окно. Окно игры должно быть полностью видно, без перекрывающих окон и уведомлений.
2. Оставьте включённым «Только наблюдение». Первую игру пройдите вручную, делая снимки каждого состояния через F9, пока бот на паузе.
3. В окне калибровки выберите состояние и выделите небольшой прямоугольник со статичным элементом интерфейса. Нажмите «Добавить шаблон области».
4. Для `lobby` выделите кнопку запуска поиска в режиме «Точка нажатия» и нажмите «Сохранить точку меню». Для `results` так же задайте возврат в лобби. Для `bus` по умолчанию используется Space; измените клавишу в настройках, если раскладка другая.
5. Повторите для необходимых состояний из таблицы. При разных вариантах одного экрана можно добавить несколько шаблонов. В текущей локальной калибровке все перечисленные этапы уже описаны.
6. Проверьте каждый сохранённый кадр кнопкой «Проверить этот кадр». Проверьте также другие кадры того же состояния: сравнение шаблона с его исходным кадром само по себе точность не доказывает.
7. Через F6 включите наблюдение во время ручной игры. Убедитесь по журналу, что состояния определяются правильно, включая остров ожидания, высадку и результаты.
8. Поставьте на паузу, выключите «Только наблюдение», вернитесь в лобби игры и нажмите F6.

| Состояние    | Что выбирать для распознавания                                         |
| ------------ | ---------------------------------------------------------------------- |
| `lobby`      | Стабильную часть доступной кнопки запуска в лобби                      |
| `searching`  | Статичный текст поиска, без меняющегося времени                        |
| `loading`    | Статичный индикатор/текст загрузки; для разных экранов нужны варианты  |
| `waiting`    | Текст острова ожидания, без цифр обратного отсчёта                     |
| `bus_wait`   | Автобус до доступного приглашения к высадке; только ждать              |
| `bus`        | Приглашение к высадке, появляющееся когда прыжок доступен              |
| `deploying`  | Элемент, отличающий спуск от нахождения на земле                       |
| `match`      | Стабильный HUD активного персонажа                                     |
| `downed`     | Значок сбитого персонажа и собственный HUD; ждать оживления/устранения |
| `eliminated` | Надпись устранения; ждать дальнейшего экрана                           |
| `spectating` | Статичный текст «РЕЖИМ ЗРИТЕЛЯ», без имени наблюдаемого игрока         |
| `continue`   | Кнопка «ПРОДОЛЖИТЬ»; задержка 6 секунд перед нажатием                  |
| `xp`         | Кнопка «ПРОПУСТИТЬ» на экране начисления опыта                         |
| `results`    | Кнопку или заголовок экрана смерти/результатов                         |

`waiting`, `bus`, `deploying` и `results` имеют приоритет над HUD матча. Это предотвращает движение по одному лишь HUD на острове ожидания или поверх экрана результатов. Не включайте в шаблон таймер, счётчик здоровья, анимированный фон, имя игрока и другие меняющиеся данные. Пустой одноцветный прямоугольник не различает состояния.

Для разных фаз спуска, экранов загрузки, смерти и победы добавьте отдельные шаблоны. Состояние «сбит, но не устранён» обрабатывается как `downed`: бот отпускает ввод и ждёт. После оживления возможно возвращение к `match`, после устранения — переход через наблюдение и меню. Отсутствие ожидаемого экрана ограничивается тайм-аутом, повторные нажатия — лимитом попыток.

В откалиброванном профиле действия задаются явно: `wait` — только ждать, `play` — эпизоды движения в матче, `key` — клавиша, `click` — точка меню. Текстовые шаблоны могут использовать метрики `white_text` и `dark_text`, сравнивающие форму надписи с допуском в один пиксель вместо цвета игрового фона. Дополнительные области `checks` должны совпасть одновременно: например, значок здоровья и собственный HUD. Меню, наблюдение, сбитый персонаж и спуск имеют приоритет над общим HUD матча. Поиск следующего матча имеет приоритет над наблюдением на заднем плане.

**Дополнительные подтверждения меню.** Для варианта экрана с другой кнопкой сначала выберите точку, затем добавьте шаблон области. Точка запишется прямо в этот шаблон как `action`. После подтверждённой смены варианта бот сможет нажать соответствующую кнопку. Все варианты одного состояния используют общий лимит попыток. «Сохранить точку меню» меняет общее действие состояния, а не уже записанные действия отдельных шаблонов.

Порог совпадения по умолчанию — `0.94`. Чем он выше, тем строже сравнение. Подбирайте его по нескольким кадрам. При изменении разрешения приложение откажется распознавать старый профиль; создайте новый `--data-dir` или выполните калибровку заново. Поиск шаблонов привязан к выбранным областям клиентской части окна.

## Настройки поведения

Все параметры доступны через «Настройки JSON» и в `runtime/settings.json`. Изменения применяются при следующем F6. Встроенный редактор проверяет диапазоны и не сохраняет некорректные значения.

| Параметр `behavior`    | Значение по умолчанию                                 |
| ---------------------- | ----------------------------------------------------- |
| `weights`              | Движение 75, осмотр 15, пауза 10 — относительные веса |
| `move_seconds`         | 3–8 секунд                                            |
| `look_seconds`         | 1–2,5 секунды                                         |
| `pause_seconds`        | 0,5–2 секунды                                         |
| `turn_pixels`          | 25–160 единиц относительного движения мыши за эпизод  |
| `turn_probability`     | 0,65 на эпизод движения                               |
| `jump_probability`     | 0,15 на эпизод движения, один прыжок                  |
| `sprint_probability`   | 0,35 на эпизод движения                               |
| `diagonal_probability` | 0,30 на эпизод движения                               |
| `turn_sensitivity`     | 1,0 — множитель величины поворота                     |
| `keys`                 | W/A/D, Space, Shift                                   |

Движение сохраняется в течение эпизода. Поворот идёт плавно по сглаженной кривой, одновременно с движением возможен прыжок. Повтор предыдущего типа эпизода получает меньший вес. Вероятности прыжка, диагонального движения и бега независимы. `SHIFT` предполагает соответствующую настройку спринта в игре.

По умолчанию включён ограничитель удаления `behavior.roaming`: выход вперёд длится максимум 2,5 секунды, затем бот идёт противоположными клавишами, делает короткую паузу и плавно осматривается перед следующим выходом. При диагональном движении возвращение также диагональное в обратную сторону. Во время выхода и возврата камера не поворачивается, спринт отключён. Клавиша назад настраивается как `behavior.keys.backward` (S). В журнале появляются записи `ROAM return`, в статусе действия — `return`.

Параметры `roaming`: `max_outward_seconds` — максимум выхода (2,5); `return_multiplier` — отношение времени возврата к времени выхода (1,0); `return_pause_seconds` — пауза после возврата (0,4–0,9); `reorient_pixels` — величина осмотра на месте (120–360 с учётом `turn_sensitivity`). `enabled: false` возвращает исходное поведение со спринтом и поворотами во время движения.

Этот режим уменьшает длительные уходы в одном направлении, включая уход в открытое море, но не распознаёт воду и не вычисляет положение берега. Возврат по времени приблизительный: столкновения, прыжки, склон, падение с обрыва и разница скорости движения могут помешать вернуться в исходную точку. Если персонаж уже в океане, режим не гарантирует выход на сушу. Для добавления распознавания плавания нужен снимок F9 с таким состоянием; среди текущих размеченных кадров его нет.

Основные параметры `runtime`: `stable_frames` — подтверждение состояния несколькими кадрами; `frame_interval` — период распознавания; `entry_delay` — ожидание перед действием меню; `action_timeout` — ожидание результата нажатия; `max_attempts` — общий лимит действий в текущем состоянии; `unknown_timeout` и `state_timeouts` — ограничения ожидания; `match_settle` — задержка движения после подтверждения матча.

## Устойчивость и границы проверки

- На первом неизвестном или неожиданном кадре игровые клавиши отпускаются. По истечении `unknown_timeout` бот переходит на паузу.
- Смена экрана подтверждается несколькими кадрами. Новое меню-действие не отправляется, пока не появился подтверждённый новый экран или не истёк тайм-аут предыдущего действия.
- При исчерпании попыток, ошибке, изменении геометрии окна или потере фокуса ввод освобождается; рабочий цикл восстанавливается согласно `recovery`. Автоматического захвата фокуса нет.
- Независимый поток каждые примерно 20 мс проверяет фокус и свежесть последнего кадра. Он отключает ввод, если основной поток завис на захвате или распознавании.
- Проверяется имя процесса и заголовок окна. Перед каждым событием ввода фокус и геометрия проверяются повторно.
- Все зажатые приложением клавиши и кнопка мыши учитываются. Их отпускание выполняется при паузе, ошибках и штатном закрытии. Принудительное уничтожение процесса или сбой ОС не позволяют гарантировать выполнение обработчиков завершения.
- Журнал с ротацией: `runtime/logs/bot.log`. Снимки для калибровки: `runtime/captures`. Диагностические кадры ошибок: `runtime/diagnostics`.

Используется стандартный Windows `SendInput`, без чтения памяти игры и внедрения кода. Его успешный возврат не доказывает, что игра приняла команду; поэтому меню проверяется по экрану. Некоторые приложения могут блокировать этот ввод. Обход блокировок не реализован. Не запускайте Fortnite с повышенными правами относительно бота: Windows ограничивает передачу ввода между разными уровнями привилегий.

В этой среде проверяются контроллер, распознавание на искусственных изображениях и модуль ввода с подменой системных вызовов. Успешное прохождение реального матча требует проверки на вашем Fortnite после калибровки. Бот не понимает игровую сцену, не ищет цели и не пытается выигрывать; движение не проверяется по положению персонажа, застревание пока не определяется.

## Проверки без отправки ввода

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m reincarnation --init
.\.venv\Scripts\python.exe -m reincarnation --check
.\.venv\Scripts\python.exe -m reincarnation --classify runtime\captures\YOUR_FRAME.png
```

`--check` возвращает код 2, пока профиль неполон. Тесты не нажимают реальные клавиши, не двигают мышь и не запускают Fortnite. Они проверяют полный цикл, распознавание искусственных кадров, повторные попытки, подтверждение экранов, неизвестные состояния, потерю фокуса и освобождение ввода.

## Устройство проекта и развитие

`config.py` — настройки и проверка профиля; `vision.py` — распознавание; `engine.py` — конечный автомат; `behavior.py` — генератор эпизодов; `windows.py` — окно, ввод и горячие клавиши; `worker.py` — рабочий поток и контроль безопасности; `gui.py` — интерфейс и калибровка.

Дальнейшие расширения: именованные профили поведения, более длинная память последних эпизодов, обнаружение застревания по последовательности кадров, пакетная проверка шаблонов на реальных снимках, дополнительные способы возврата в следующий матч. Эти функции пока не реализованы.

Документация используемых API: [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput), [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey), [Pillow ImageGrab](https://pillow.readthedocs.io/en/stable/reference/ImageGrab.html).
